# Сборка с тремя проверенными удалениями

Первоначально изменение проверялось отдельной локальной сборкой. По запросу
пользователя оно включено в публикацию через `tools/watch_game.py`.
Переключатель — `patches/client-check-policy.json`: `enabled: true`.
Причина конкретного серверного отключения пользователя всё ещё не доказана.
Резервная версия и откат описаны в `ROLLBACK.md`.

Удалены три проверенных участка текущего клиента:

- тело `ᴀ̅︋`, проверявшее API браузера, их исходный текст и стек вызовов;
- код `ᴀᄁᄀ`, искавший известные ID меню, включая `tab-aimbot`, `aimtog`,
  `kb-aim` и префиксы `grok-`, `omrx-`, `baba-`, `dvx-`;
- проверка `document.currentScript.src` на имя `8arQWmH5bsutMu.js`.

Имена вызываемых функций сохранены с пустыми телами, чтобы существующие вызовы
не ломали клиент. Код двух обфусцированных блоков физически удалён из результата.
Не добавлены перехват Function.toString, смена IP, сброс куки или подмена
сообщений сервера. Серверные проверки этим файлом не изменяются.

Сборщик требует точный SHA-256 исходного игрового клиента и точные хеши всех
трёх удаляемых участков. Изменённый или неоднозначный участок останавливает
сборку. В диагностике указан режим `three-client-checks-removed`: флаг 0
в этом режиме нельзя считать прохождением исходной проверки.

## Проверка команд

200 обновлений цели проведены через точную функцию штатной отправки клиента.
Для прицеливания получены только массивы `[6, целый_угол_0…359]`. Для автоогня
получены `[4]` и `[5]`, совпадающие с нативными функциями нажатия и отпускания.
Попыток HTTP/fetch/beacon из проверенного пути аимбота не было. Этот тест
использует наблюдатель вместо кодировщика и не является сетевой проверкой
оружия. Отдельно побайтно сравнены кодировщик, шифрующий обработчик,
отправщик WebSocket и обработчик получения токена: они не изменились.

Удаление клиентской проверки не скрывает от сервера обычные игровые команды,
их частоту и углы; отдельный пакет «аимбот включён» в этом пути не найден.

## Контрольные браузерные пробы

Для этих проб сервис токенов и игровые WebSocket были заблокированы, чтобы
тестовые сигналы не отправлялись серверу. Проверки вызывались явно через
отладочный протокол; это отличается от естественного порядка подключения.

Добавленный элемент `tab-aimbot` вызвал флаг 1 у исходного DOM-сканера;
чистая страница после вызова только DOM-сканера сохранила 0. Другой URL JS
вызвал отдельный флаг имени файла 1; вариант с удалённой проверкой сохранил 0.
В варианте с удалёнными проверками оба вызываемых тела пусты и эти пробы
не устанавливают флаг. Явный вызов проверки API дал 1 также в чистом контрольном
клиенте: он не позволяет приписать срабатывание именно моду или обёртке API.

При параллельной загрузке тестовых страниц наблюдались четыре ошибки
декодирования аудио в одном контексте. Они отмечены в исходном отчёте;
результаты одиночного запуска игры записываются отдельно.

В одиночном запуске вариант вошёл на Frankfurt Survival 1 и работал
65 секунд после включения аимбота. Около 6,1 секунды была активная цель,
около 4,1 секунды удерживалась ручная атака при активной цели. Серверной
смерти и ошибок JavaScript не наблюдалось, соединение в конце оставалось
в состоянии 1. Это стартовое снаряжение: стрельба AK47/лазером и длительное
преследование цели этим запуском не подтверждены. Причина первоначального
кика пользователя и отсутствие будущих киков не установлены.

Ранние чтения флага 0 в меню до явного вызова проверок не доказывают, что
проверка уже исполнялась и была пройдена.

## Проверки сборки

Для публикации пройдены 61 JavaScript-тест, 12 Python-тестов и проверка
синтаксиса итогового JS. Прежние локальные Resource Override-файлы содержат
старые тестовые сборки целиком; они не начинают загружать GitHub автоматически.
Опубликованный файл находится по стабильному пути `dist/game.modded.js`.
Для сравнения следует отключить прежнее правило, а не применять обе сборки
одновременно. Сохранять Connection → Save diagnostics после отключения
до перезагрузки вкладки.

Сборка:

```bash
python3 tools/watch_game.py --once
```

При включённом переключателе удаление выполняется после обычных патчей
и до проверки синтаксиса и атомарной замены выходного файла. Для новой
основы с неизвестным SHA-256 публикация останавливается: удаления не
переносятся предположительной заменой имён и не теряются при пересборке.
