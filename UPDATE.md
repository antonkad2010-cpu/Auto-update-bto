# Повторяемое обновление BBY

1. Прочитать AGENTS.md, README.md, LIVE-CHECK.md, mod/bby.js,
   mod/current-adapter.js и patches/manifest.json. Проверить git status.
   Использовать существующий checkout; отдельный worktree создавать только
   по явному запросу пользователя.
2. Запросить https://devast.io/ с браузерным User-Agent, сохраняя проверку TLS.
   Использовать tools/fetch_current.py; имя бандла находить по script src,
   не использовать постоянное имя файла. Сохранить оригинальную основу,
   URL, размер и SHA-256 до изменений.
3. Если хеш совпал, не выполнять фиктивное обновление. Проверить текущую сборку.
   Если изменился, сопоставить поля игрока, команд, камеры, сущностей,
   принадлежности к клану, владельца здания и доступного предмета заново.
   Не переименовывать обфусцированные идентификаторы глобальной заменой.
4. Сверить аимбот с предыдущей реализацией: выбор целей, история координат,
   упреждение, единицы угла, jitter и порядок angle-before-fire.
   Сохранить поздние исправления: линия совпадает с отправляемым направлением;
   при удержании огня jitter не подменяет угол упреждения.
5. Обновить адаптер и точные уникальные якоря манифеста. Сначала подтвердить
   соответствие новой основы, затем записать её хеш. Не отключать проверки
   уникальности, TLS или проверки целостности загрузок.
6. Выполнить node --test tests/bby.test.cjs и
   python3 -m unittest discover -s tests -p 'test_*.py'. Обновить тестовые
   фрагменты текущего клиента при изменении версии. Собрать через
   tools/apply_patches.py и выполнить node --check build/game.modded.js.
7. В браузере подменить именно актуальный URL бандла собранным файлом.
   Проверить раскрытие разделов меню, H/Z/Q/T, индикаторы слева по центру,
   подписи #ID и владельцев зданий. Сохранять TLS-проверку. Проверить текущую
   сетевую политику, доступ к webgames.io и игровым поддоменам.
8. Для входа может понадобиться дождаться рекламы после Play. Не считать
   рекламу игрой. Подтвердить игровые пакеты и живого игрока, затем наблюдать
   минимум 60 секунд непрерывно. Отдельно указывать, какие функции были
   включены. Ошибки JS, закрытия WebSocket и причины отключения записывать
   без токенов и других секретов. При неудаче сравнить с чистой основой.
9. Обновить LIVE-CHECK.md с фактически выполненными проверками и ограничениями.
   Выдать build/game.modded.js и отчёт о результате. Не объявлять непроверенные
   функции рабочими и не гарантировать прохождение серверного античита.

## Известные особенности среды

Python 3.12, Node.js 22. Chromium установлен в /usr/bin/chromium.
В текущем экземпляре вспомогательные инструменты были в
/workspace/.devast-setup/analysis, но эти локальные файлы не гарантированы
в новой среде. Не полагаться на их наличие без проверки.

Для Chromium требовался доступ к /home/agent/.pki/nssdb: сертификат прокси
уже присутствовал, но недоступная для записи NSS-база приводила к
ERR_CERT_AUTHORITY_INVALID. Не обходить TLS-проверку; при необходимости
использовать предусмотренный платформой запрос разрешений.

Сохранённая сетевая конфигурация и её применение различаются. Если Widget
не определён и webgames.io возвращает 403, проверить актуальное состояние
политики. Не выдавать эту ошибку за серверный кик.
