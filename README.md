# Монитор текущего клиента

`tools/watch_game.py` проверяет игровой сайт каждые 120 секунд, пока процесс
работает. Для одиночной проверки:

```sh
python3 tools/watch_game.py --once
```

Для постоянной работы нужна отдельная всегда включённая машина или сервис:

```sh
python3 tools/watch_game.py --interval 120
```

Если SHA-256 игрового JS совпадает с `patches/responsive.json`, процесс
запускает тесты, собирает клиент и проверяет синтаксис. Файлы появляются в
`build/watch/`: `game.modded.js`, `report.json` и `status.json`. При новом хеше
статус становится `new_version_needs_remapping`; существующий файл сохраняется
как старая сборка. Он не является обновлением для нового JS. При ошибке загрузки
или проверок статус `check_failed`. Просматривайте `status.json` перед выдачей
файла: сам файл после появления новой версии может быть устаревшим.

Бот не выполняет автоматический перенос на неизвестную версию и не проверяет
поведение в игре. Обфусцированные имена и точки подключения должны быть заново
сопоставлены и проверены, как указано в `UPDATE.md`.

`.github/workflows/watch-responsive.yml` запускается вручную или каждые пять
минут (расписание GitHub Actions не поддерживает двухминутный интервал и может
задерживаться). Результат — артефакт `responsive-game-check`, сохраняемый семь
дней. Для приватного репозитория доступ к артефакту требует авторизации и прав
на репозиторий. Сам по себе этот workflow не создаёт постоянно работающий бот
и не предоставляет анонимную публичную ссылку.

Ветка `main` содержит последнюю совместимую сборку в `dist/game.modded.js`.
При каждом успешном запуске workflow обновляет этот файл, если сборка изменилась.
При обнаружении неизвестного хеша workflow удаляет его из текущей ветки до
повторной проверки привязок. Если сайт недоступен, задача не может установить
актуальность последней сборки: проверяйте результат последнего запуска Actions.
Для записи workflow требуются разрешения GitHub Actions на contents: write.

Приватный файл доступен только авторизованным пользователям. Его raw URL не
является анонимной ссылкой и может не работать в Requestly без авторизации;
не вставляйте токены доступа в файл правил или страницу игры.

Экспериментальный workflow `publish-script.yml` подготавливает GitHub Pages с
единственным файлом `game.modded.js` после проверки известной версии. Он не
публикует исходники бота. Для работы GitHub Pages должен быть доступен для
приватного репозитория в тарифе аккаунта и настроен на публикацию через Actions.
При неизвестном хеше workflow публикует страницу о необходимости переноса,
без старого JS. Доступность Pages и сам запуск необходимо проверить в Actions.
